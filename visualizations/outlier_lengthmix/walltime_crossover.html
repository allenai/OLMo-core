The exchange rate is measured, not modelled: dense 0.00552 vs sparse 0.00332 node-hours per million tokens (1.66× faster), fitted from every arm's job start and exit times. So sparse can lose on data and still win on time -- anywhere it needs under 1.66× dense's tokens for the same score, it is the cheaper route. A FLOP count would have predicted only ~1.1×, since attention is barely a tenth of the arithmetic in this 3:1 GDN hybrid; the rest is kernel and memory behaviour.

The speedup is not a constant — it grows with training length

Every panel above uses the measured 1.66×, which is the rate at the 4k–9k mixes our arms actually trained on. That badly understates sparse for long-context training: dense pays attention proportional to L per token while sparse pays about L/64, so the advantage widens with the mix. Anchoring the standard attention split on our two measured rates (c_params = 0.00329 h/Mtok, c_attn = 3.36e-7 h/Mtok per token of L) gives:

Sparse wins on time exactly when speedup(L) > R, where R is the factor more tokens it needs for the same score. On outlier R is only 1.4–2.0, so sparse is already cheaper at the 16k rung and would be at every rung with a 10k training mix. On oolong R is 3.4 and break-even is a 24k mix. On the tasks where sparse never reaches dense's score at all — contradiction, reorder, qdmatch, grouping, textgroups — R is infinite and no training length rescues it: that deficit is representational, not economic.

⚠ The length dependence is a MODEL. Every arm trained at 4k–9k, so the data pins the rate at one length and says nothing about its slope. The L-scaling is the textbook quadratic-attention argument; it assumes the 1/64 landmark ratio survives at long context and ignores memory pressure that at 1M would likely dominate. The 1.66× row is measured; the 40× row is an argument.
