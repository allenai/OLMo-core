## Gates and monitoring

1. Actual production-image CPU job verifies all 16 runtime package versions,
   fixed KDA source hashes, real configs for fresh start and resume for both arms,
   and a small readable token sample from every active MT source.
2. A CPU controller stages an independently SHA256-verified full checkpoint for
   each completed decay. Non-EMO waits for its exact endpoint, not the stable run.
3. Submit exactly one 64GPU training experiment per arm. Before the long pass,
   validate initial weight/buffer restoration and optimizer reset on all64 ranks,
   train two steps, save, restart and verify full MT state/RNG/data restoration.
4. Final successful MT checkpoint triggers conversion -> precise export/runtime
   qualification -> the existing provisional fast OLMoBase Gen/MCQA, Math, Code
   v2/FIM suites. The numerical workers/recipes remain frozen, with only scoped
   identities/paths/MT steps changed. GPU eval workers stay allocated on the
   existing Jupiter/Ceres templates in ai2/OLMo-3-moe-experiments.
5. The controller monitors final upload verification and evaluation receipts.
   Failures are reported, not automatically multiplied into retry jobs.
