Beyond the grid

Four measurements from 2026-08-13 that the 2k–32k grid cannot express — a length axis, a model-scale axis, a document-count axis, and a harness audit — but that change how some of its columns should be read.

oolong is flat on BOTH arms — dense 0.5727 → 0.5733 and chunked 0.5539 → 0.5544 from 32k to 64k, one full octave beyond anything either was trained on, with the dense-chunked gap holding constant at ~0.019. So the chunked mask is not what limits length generalization here; whatever caps oolong caps both arms equally. rerank and msmarco lose little at 64k and then fall at 128k. The O(N²) rows fall first and hardest: contradiction drops 0.946 → 0.278 in a single octave.

Chunked eval above 32k is memory-bound, and the knobs do not transfer. The chunked 64k run first died allocating a 74 GiB boolean attention mask. The fallback mask costs O(num_actual_tokens x total_cache_tokens) with total_cache_tokens = max_model_len x CHUNK_SEQ_HEADROOM, so the fast-eval knobs (seqs 16 / headroom 18, tuned and validated at rung ≤ 8192) are ~4x too expensive at 64k on top of the mask's own quadratic growth in rung length. gpu_eval_task_chunked.sh gates those knobs to rung ≤ 8192 for exactly this reason; the oolong launcher sets CHUNK_FAST_MAX_RUNG=99999999 to defeat the gate because they are part of the varlen recipe — but varlen did not engage on this model, so the run got the varlen config's memory cost with the fallback path's memory profile. Re-run at the default 8/10 it completes in 45 min. More GPUs would not have helped: the mask is a [query x key] tensor shared across heads, and tensor parallelism shards heads, not positions.

Only injection-safe tasks appear above. The long rungs are built by injecting filler documents, which is sound when gold is defined by matching a query or a partner (query_match, pairwise) and unsound when gold is defined by what is absent or by global structure (absence, structural) — there, injected fillers silently create unlabeled golds. So the 64k/128k numbers for outlier, outlier amazon, cycle, textgroups, absence and xabsence are retracted and deliberately not shown; they need natively-generated rungs. The rule is encoded as gold_semantics in debug/ctc_modelscale/expand_ctc_rung.py.

Two tasks have a capability threshold, and they sit at different places. qdmatch nq is at zero on both arms at 0.8B — 0.039 and 0.033 at 2k, decaying to 0.000 — and then works at 2B (0.995 dense at 2k). That is not a chunking effect and not underfitting: the same 0.8B base learned contradiction to 0.962 and hpqa to 0.995 on the same wave of runs, while qdmatch's training CE plateaued at 0.78 against 2B's 0.06. reorder's threshold is one step higher: it is at chance at 0.8B and 2B (|kendall_tau| < 0.01 at every rung) and only becomes a task at 4B, where it reaches 0.747 at 2k.

Scaling does not close the CTC gap — on the hardest task it widens it. hpqa (O(N) retrieval) is saturated at 0.8B and has no gap at any scale. But qdmatch nq goes from no-measurable-gap at 0.8B (both arms dead) to +0.484 at 2B to +0.582 at 4B, because the dense arm keeps improving while the chunked arm gets worse from 2B to 4B (0.179 → 0.104). Contradiction narrows slightly, +0.321 → +0.247. So a bigger model is not a substitute for the attention pattern.

Four cells are missing, and two of them for an unexplained reason. fiqa was only run at 0.8B, so it has no 2B column. But contradiction and reorder have no 0.8B chunked arm: those two runs OOM at 0.8B × chunked-mix × seq_len 40960 on both saturn and jupiter, while the same config at 2B and 4B trains fine and 0.8B at 33792 also trains fine. Four hypotheses (activation checkpointing, sharding, architecture shape, shard length) were each tested and refuted. Until that is understood, read the 0.8B column as dense only — do not infer a gap from its absence.

The outlier fix-k “32k cliff” is not a cliff — which is why 32k is not in the grid

The ladder held ~0.95 to 16k and then read 0.319 at 32k on both arms, which looked like a length limit or a training-support boundary (training sampled n ~ U[14,220], and the 32k rung is n=220). Filling the 111 → 220 gap shows neither: it is a smooth monotone decline that continues past the training support. Rendered as the last column of a 2k–32k ladder that single point reads as “collapses at 32k”, which is the one thing it does not do, so the fix-k row stops at 16k and the real shape is shown here against n:

The stop-token bug is real, and it costs nothing

stop_token_ids ships only <|endoftext|> (248044), but our SFT targets end the assistant turn with <|im_end|> (248046), so vLLM never stops — the model answers and then repeats itself to the token cap. Tasks graded with stop="newline" are protected by an accidental text-level cut; the seven on stop="eos" are not. That looked like it could invalidate rows: reorder's parse_rate decays 0.95 @4k → 0.654 @8k → 0.16 @16k, and a score that falls while parse_rate falls with it cannot be told apart from a length effect.

It does not invalidate anything. A/B on identical prefills, changing only the stop token, at 4B:

Reading the numbers

Error bars. Each ± is the binomial standard error sqrt(p(1-p)/eval_size). For a per-example metric valued in [0,1] the Bernoulli variance is the maximum, so this is an upper bound on the true SE, not an estimate of it — the graders do not persist per-example scores. Run-to-run seed variation is on top of this and is not measured here.

eval_size is 500 everywhere except scifact (300, ±.019 at f1≈0.93) and obliq (126, ±.042). Those two are flagged in amber in the grid and no sub-0.05 difference on them should be read as real.

Gap is dense minus chunked at the deepest rung where both arms have a number, with that rung noted underneath. It is the CTC quantity: flat across the ladder for O(N) tasks, widening for O(NM) and O(N²).

Two different contradiction rows. Row 18 is NIAH-contradiction, a retrieval task. Row 19, contradiction (realistic), is the PubMed multi-claim task — a different task, added here as the 22nd row.

The realistic row is scored on the IID ladder, and that choice is the whole result. Training is realistic-mode gold pairs; every earlier contradiction number was scored on a both-mode eval, a different generator whose gold pairs are 38% near-duplicates. On that mismatched ladder the same dense checkpoint reads 0.843→0.559 and chunked 0.402→0.191. Swapping in the mode-matched ladder, with nothing retrained, gives the row shown: dense 0.990→0.946 and chunked 0.861→0.699. So dense does not collapse with corpus size — 13.6× more documents costs 0.043 f1 — and the dense-chunked gap widens with n (0.128→0.247) instead of narrowing. Do not mix the two ladders in one figure; see records/contradiction-train-eval-non-iid.md.

Its 2k column is the rung_2560 / n=56 file: n=44 sat below the training minimum of 52, so the IID rebuild starts one step up. The other four rungs are n-identical to the old ladder (92 / 187 / 379 / 762), which is what isolates the mode as the only change.

Provenance. Numbers are harvested from the node-local ctc_suite_vllm_results{,_chunked} and ctc_newrung_results trees by debug/ctc_final_suite/harvest_grades.py; when a cell exists on more than one node the newest file wins. Two rows come from elsewhere: outlier fix-k and qdmatch nq were backfilled by the model-scale drivers and are read from debug/ctc_modelscale/results_4b/, filtered to 4B by run name so that no 0.8B or 2B cell can leak into this grid. Roster and coverage notes live in records/ctc-final-suite.md.

The scale table is built against the grid, not beside it. build_scale_table.py reads the 0.8B/2B cells from debug/ctc_modelscale/results/ and takes the 4B column by reading suite_table.json back, so the scale figure and the grid cannot disagree about what 4B scored. Every scale cell was verified to sit on the same ladder as its 4B row from the eval_data path in its grade JSON — contradiction on eval_rungs/contradiction_iid, not the both-mode ladder, whose copies are kept in a separate __BOTHMODE directory and excluded by the run-name pattern. A scale plot built across two different eval sets would read as a capability curve.

oolong is pinned to the retrain, not to “newest”. Newest-file-wins resolves duplicate grades of the same model; it cannot resolve two different models sharing a task directory, and oolong has exactly that — ctc-4b-oolong-* (original) and ctcms-oolong-*-4b-vsl (the retrain that fixed it). Left alone the grid rendered oolong as dense 0.232 vs chunked 0.628 at 2k, i.e. the dense arm losing badly, purely because the dense arm was the broken original and the chunked arm was not. The row now shows the retrained pair on both sides (0.710 vs 0.691) and is pinned by run name, so a later re-grade of the original cannot quietly take it back.
