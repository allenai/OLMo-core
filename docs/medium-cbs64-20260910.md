The controller first validates all configs in the qualified CPU image, then
holds64GPUs for the bounded resume/speed passes, then submits the128GPU
comparison. Only after all gates succeed does it submit both64GPU CBS arms.
Dependency waits consume no training GPUs. All training jobs are urgent,
allocated1h, in `ai2/olmo3p5-training`, on Holmes, excluding485/503/516.
No automatic training retries; a failure blocks downstream launches for review.
The CPU controller and CPU config gate run on Triton, urgent/unallocated with
zero GPUs. They do not consume the workspace's GPU allocation. The original
never-started Rhea controller was canceled before submitting its replacement.

Each timing pass discards its first20updates and reports harmonic-mean effective
TPS and median TPS over all40remaining updates, including metric-drain waits.
Complete route-drop and skipped-update telemetry is required; skipped measured
updates block promotion. Nonzero route drops are reported, not called dropless.

Restore checks cover every state key using the parent checkpoint's128-element
sample convention, not full-tensor equality. For128->64 optimizer resharding,
both mapped old shards are checked against the corresponding new shard halves.
Model weights, buffers, rolling histories, global tokens and loader position
are also checked. Final64GPU probe checkpoints are reloaded by fresh agents and
run for one further update. Synchronous saves must preserve sampled live state.

Both CBS arms restart from the original67.108864B fork, not a probe endpoint.
They hard-stop at100.663296B (globalstep5000 /4500). The scheduler's horizon is
later than the stop, keeping the stable LR throughout. In-loop eval cadence is
500 /250steps plus final evaluation, matched in tokens. Checkpoint cadence is
8.388608B tokens for both branches.

Only campaign-owned roots are registered with the existing private test bucket
and uploader: verified-safe deletion, keep2, grace1h, separate lineage/prefix
per saved phase. The original parent remains untouched and protected. No
checkpoint/data payloads are written into Beaker results. No manual Weka deletion.
